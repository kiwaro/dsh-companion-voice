# 桌宠语音整体设计

项目位于 `D:\work\dsh-companion-voice`，作为独立 DSH 插件维护。宠物主体继续位于 `D:\work\dshPlugIn\dsh-companion-lanxi`。

## 用户流程

用户开启语音后，原生后台进程采集所选麦克风。用户说“嗨大肥鱼”，宠物显示并播报“我在”，进入提问状态。唤醒词和问题可以连说。模型回答后进入可继续提问的短暂窗口，超时回到唤醒待机。关闭语音后立即释放麦克风，停止播报和本次语音任务。关闭宠物同样暂停收音。

识别出的自然语言全部交给原有统一执行器。问答、移动宠物、操作任意应用或浏览器，由现有模型和真实工具决定；语音项目不另建指令关键词白名单，不硬编码网址和应用名。仅唤醒、结束对话及停止播放属于语音层控制。

## 模块边界

1. `lib/index.js` 是 DSH 装配入口，建立宿主服务和设置路由，管理原生进程。
2. `lib/host.js` 管理配置、认证的回环通信、官方识别服务与宠物桥接。只有本地 worker 可以提交录音及主动指令。网页端只配置和查询状态。
3. `native/worker.py` 管理麦克风、VAD 分段、识别任务、对话状态和播报。网络及合成放在独立线程，不阻塞采集。
4. `native/dialogue.py` 管理唤醒、跟进窗口、结束词、回声文本过滤及代次。过期识别结果、已取消任务的回复不得重新播放或执行。
5. `native/audio.py` 使用 PortAudio 原生收音；`native/speaker.py` 播放本地 CosyVoice PCM 分块；`native/cosy_engine.py` 管理私有标准输入输出连接，`native/cosy_server.py` 在独立 Python 3.10 环境加载官方 CosyVoice 3 模型。
6. 宠物主体仅新增 `companionLanxi` 宿主桥接服务及语音设置卡片。动作执行、操作核对、气泡和会话历史沿用原有实现。语音进程不抢占宠物执行器租约。

## 官方识别

通过 `ctx.get('speechToText')` 查询当前服务，选择 `location === 'host-local'` 的官方 SenseVoice。调用 `resolve({audio, providerId, language:'zh'})` 和 `transcribe(spec, signal)`，只获取识别结果，不写主聊天会话。准备状态通过 `snapshot()` 查询，用户开启语音时由宿主启动模型准备，页面关闭不取消准备任务。

插件包含官方识别服务不等于服务已激活或模型已准备。部署需核实官方 bundle 已加载、模型下载完成、真实 WAV 可以识别。不得在官方服务不可用时把音频静默转发云端。

## 费用和数据

收音、唤醒匹配、SenseVoice 识别和 CosyVoice 本地播报不调用收费语音 API。只有唤醒后接收的用户问题进入已配置的 HY4。原始音频和转写默认不落盘，诊断只记录阶段、错误码和耗时。连接令牌存入当前用户私有目录，不放在命令行或网页响应中。

## 生命周期和取消

每次启动生成随机令牌，通信仅接受回环来源，禁止重定向和带 Origin 的 worker 请求。配置修改带修订号，拒绝旧页面覆盖新设置。DSH 卸载插件时停止 worker 并撤销路由。worker 定期确认宿主进程与连接代次，连接失效则释放麦克风。开启时单实例，异常退出会退避重启。

语音取消只取消由语音桥接发起且仍活跃的任务，不中止用户通过其他入口启动的任务。宠物禁用、执行器更换、宿主重载时，旧语音任务失效。

## 首版播报与打断

播报使用 Fun-CosyVoice3-0.5B-2512，当前默认音色来自官方仓库的 `asset/zero_shot_prompt.wav`。首次启动预提取参考音色并保存在进程内，后续请求复用模型和音色特征。下载脚本读取本机代理环境，部署脚本可继承 Windows 已启用的本机 HTTP 代理；本机 DSH 通信始终显式禁用代理。模型准备完成前暂停收音，设置显示加载状态。普通语速支持分块合成后立即播放；调整语速时遵循官方实现，改用非流式合成。

语音文本通过 JSON 标准输入传递给受管理的私有子进程，不启动网络监听，不作为命令执行。取消后立即停止旧音频播放，丢弃旧代次音频；后台排空本次生成，避免与下一次生成竞争同一模型。关闭语音、关闭宠物或插件释放时结束合成进程，释放显存。合成失败会显示错误，不静默退回系统音色。

设置提供固定文案的“试听音色”操作。请求需要同源校验、语音启用、宠物可执行、声音就绪且无活跃模型指令；试听不调用 HY4，也不修改已保存设置。用户问题、模型回答及合成音频默认不写日志或落盘，官方代码的正文日志在合成子进程内被关闭。

播报期间持续识别，过滤与当前播报相符的回声文字；识别到唤醒词、停止词或有效新提问时取消旧任务并停止声音。该方案仍是识别后打断，没有硬件回声消除；外放环境的误唤醒和延迟必须通过真人实测，不能宣称帧级全双工。

## 验收

合成进程就绪前会预生成固定的“我在。”并仅在内存中缓存波形，缩短唤醒应答等待时间。Python 3.10 基础运行时随独立项目保存在 `runtime/python310`，避免 DSH 后台依赖 uv 用户私有目录的访问权限。

分别验证：唤醒前不得调用模型；单独唤醒和连说；跟进和超时；取消期间旧结果丢弃；播报回声不作为指令；关闭释放麦克风；官方本地服务与合成音频实测；宠物动作及浏览器/桌面既有回归。合成语音回放测试与真人麦克风测试分开记录。
